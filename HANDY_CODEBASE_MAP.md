## 3. Implemented control and data flow

```mermaid
sequenceDiagram
  participant K as Bangla hotkey
  participant C as TranscriptionCoordinator
  participant A as TranscribeAction(BanglaRomanization)
  participant R as AudioRecordingManager
  participant D as Deepgram STT
  participant L as Selected Romanization LLM
  participant P as Existing paste layer

  K->>C: transcribe_bangla_romanized press/release or toggle
  C->>A: start / stop with the same binding ID
  alt Process while recording
    A->>D: open authenticated WebSocket
  end
  A->>R: shared 16 kHz mono recorder + selected VAD policy
  alt Streaming mode
    R->>D: bounded, non-blocking 16 kHz linear16 frames while speaking
  end
  R-->>A: Vec<f32> after recording stops
  alt Streaming mode is healthy
    A->>D: CloseStream after the recorder drains
  else Batch mode or recoverable streaming failure
    A->>D: completed in-memory PCM WAV, one batch request
  end
  D-->>A: validated BanglaTranscript
  alt Romanization enabled
    A->>L: raw Bangla text and selected provider settings
    alt Romanization succeeds
      L-->>A: non-empty RomanizationResult
      A->>P: paste Romanized text
    else Romanization fails after STT succeeds
      A->>A: emit content-free Romanization error
      A->>P: paste verified raw Bangla fallback
    end
  else Romanization disabled
    A->>P: paste verified raw Bangla text
  else STT fails or either stage is cancelled
    A->>A: emit STT error or suppress result; no paste
  end
```

Important behavior:

- Batch is the default: audio remains local while recording and upload begins only after stop.
- Streaming sends 16 kHz mono frames that pass the configured recorder/VAD policy while recording. The complete captured recording remains in memory until the route finishes so one recoverable WebSocket failure can fall back to batch.
- The recorder still supplies mono 16 kHz `Vec<f32>` samples and shared VAD, sounds, tray state, overlay, push-to-talk/toggle, and Escape cancellation behavior.
- WebSocket/PCM work runs off the capture worker behind a bounded queue. Batch STT and Romanization run in the async action task. Cancellation aborts the live connection, drops later stages, and generation checks prevent a late paste.
- Bangla never loads a local model, starts local streaming inference, writes a WAV, or creates a history entry.
- Streaming collects provider final segments internally and emits no live partial text. Romanization is invoked once, only after one complete transcript has been validated.

## 4. Mode, shortcut, and action routing

`src-tauri/src/transcription_mode.rs` is the source of truth for route identities:

| Binding ID                     | `TranscriptionMode`       | Local inference | Optional English post-processing |
| ------------------------------ | ------------------------- | --------------- | -------------------------------- |
| `transcribe`                   | `Local`                   | yes             | no                               |
| `transcribe_with_post_process` | `LocalWithPostProcessing` | yes             | yes                              |
| `transcribe_bangla_romanized`  | `BanglaRomanization`      | no              | no                               |

`settings.rs::get_default_settings` persists the Bangla binding. Defaults are Option+Shift+B on macOS and Ctrl+Shift+B on Windows/Linux. Existing stores receive a missing binding through normal settings default merging.

`actions.rs::ACTION_MAP` assigns each binding a `TranscribeAction { mode }`. `ShortcutAction::start` and `ShortcutAction::stop` branch on `mode.uses_local_inference()`; the Bangla branch calls `start_bangla_recording` and `stop_bangla_recording`. `transcription_coordinator.rs` recognizes this binding through `transcription_mode::is_transcription_binding`, so it retains the existing one-operation invariant, PTT/toggle behavior, release grace, busy rejection, and finish notification.

Do not replace the local `TranscribeAction` path when changing Bangla behavior. Keep the mode branch isolated.

## 5. Deepgram batch and streaming transcription

### Boundary and contracts

`src-tauri/src/bangla_transcription/mod.rs` is the provider-neutral STT boundary.

| Symbol                        | Responsibility                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| `RecordedAudio`               | Validates non-empty recorder samples, records `16_000` Hz/mono format, and caps input at nine minutes. |
| `BanglaTranscript`            | Requires a non-empty, trimmed final Bangla transcript.                                                 |
| `CancellationContext`         | Shared pull-based cancellation closure used by both cloud stages.                                      |
| `CloudTranscriptionError`     | Stable, content-free error categories for UI/logging.                                                  |
| `BanglaTranscriptionProvider` | Adapter trait: accepts `RecordedAudio`, settings, cancellation; returns `BanglaTranscript`.            |
| `transcribe_bangla`           | Dispatches the configured provider. It does not call local `TranscriptionManager` on failure.          |

The error categories are `missing_configuration`, `unsupported_provider`, `invalid_configuration`, `empty_audio`, `audio_too_long`, `offline`, `timeout`, `authentication`, `rate_limited`, `provider`, `malformed_response`, and `empty_transcript` (plus internal `cancelled`). Events and logs use only these codes—never a key, endpoint, audio, transcript, or response body.

### Current Deepgram adapter

`src-tauri/src/bangla_transcription/deepgram.rs` implements `DeepgramNova3Provider`.

- Provider ID: `deepgram`.
- Request: `POST /v1/listen`, `Authorization: Token <user key>`, `Content-Type: audio/wav`.
- Query: configured model (default `nova-3`), `language=bn`, `smart_format=true`.
- Audio: a 16 kHz mono signed-16-bit PCM WAV built entirely in memory by `encode_wav`; no WAV file is persisted.
- Response: `results.channels[0].alternatives[0].transcript` must be present and non-blank.
- Network policy: 45-second connect/request timeout; request failures map to offline, timeout, or provider; 401/403 map to authentication and 429 to rate limit.

Deepgram configuration is intentionally separate from `selected_model` and English post-processing:

```rust
bangla_stt_provider_id
bangla_stt_endpoint
bangla_stt_api_keys["deepgram"]
bangla_stt_models["deepgram"]
bangla_stt_mode // Batch (default) or Streaming
```

### Streaming manager and adapter

`streaming.rs::BanglaStreamingManager` is created in `lib.rs`, shared with `AudioRecordingManager`, and owns at most one live attempt. `feed` performs only an atomic inactive check, sample-limit accounting, a frame copy, and `try_send` into a bounded queue; it never performs encoding or network I/O on the recorder worker. The complete recorder output is retained separately for fallback.

`deepgram_streaming.rs` owns the wire protocol:

- `wss://.../v1/listen` with token authentication and `model`, `language=bn`, `smart_format=true`, `encoding=linear16`, `sample_rate=16000`, and `channels=1` query parameters;
- signed 16-bit little-endian PCM binary frames;
- content-free keep-alives every four seconds while recording;
- `CloseStream` only after the recorder has drained its final resampled/VAD-filtered frame;
- ordered, de-duplicated `is_final` result segments, completed by terminal metadata/server close;
- 10-second connect and 20-second provider-finalization deadlines.

Credentials, invalid configuration, rate limits, explicit cancellation, and the nine-minute limit are terminal. Connection, timeout, server, queue-overflow, malformed/empty response, and unsupported-WebSocket failures are recoverable and trigger at most one HTTP batch request. A fallback never causes a second Romanization call.

To add a different STT provider, add an adapter module implementing `BanglaTranscriptionProvider`, dispatch it in `transcribe_bangla`, extend allowed provider settings/defaults/UI metadata, and write a secrets-free mock-server contract test. Do not put provider HTTP code in `actions.rs`.

## 6. Optional LLM Romanization

`src-tauri/src/bangla_romanization.rs` is a separate semantic service. It is invoked only when `bangla_romanization_enabled` is true and must not be merged into `llm_client.rs`, because the latter serves optional English post-processing with intentionally fail-open behavior.

### Boundary and validation

| Symbol                       | Responsibility                                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `RomanizationInput`          | Accepts a non-empty trimmed Bangla transcript.                                                                   |
| `RomanizationResult`         | Accepts every non-empty trimmed result, including a mostly Romanized value that retains a few Bangla characters. |
| `RomanizationError`          | Content-free error category returned to the action/UI.                                                           |
| `BanglaRomanizationProvider` | Provider-neutral adapter trait for a required semantic stage.                                                    |
| `romanize_bangla`            | Dispatches the selected Groq, Gemini, or OpenAI adapter.                                                         |

Romanization error codes are `missing_configuration`, `unsupported_provider`, `invalid_configuration`, `empty_input`, `offline`, `timeout`, `authentication`, `permission_denied`, `rate_limited`, `invalid_request`, `model_unavailable`, `provider_unavailable`, `provider`, `malformed_response`, and `empty_result` (plus `cancelled`). The action emits only the code through `bangla-romanization-error`.

### Providers and request shapes

| Provider ID | Adapter/API shape                             | Authentication          | Default model           |
| ----------- | --------------------------------------------- | ----------------------- | ----------------------- |
| `groq`      | OpenAI-compatible `POST /chat/completions`    | `Authorization: Bearer` | `openai/gpt-oss-120b`   |
| `gemini`    | `POST /v1beta/models/{model}:generateContent` | `x-goog-api-key`        | `gemini-3.1-flash-lite` |
| `openai`    | `POST /chat/completions`                      | `Authorization: Bearer` | `gpt-5.6-luna`          |

Groq and OpenAI request `stream: false`. Groq uses strict JSON Schema output for the GPT-OSS 20B/120B model IDs and JSON-object output for other user-entered Groq models; OpenAI uses JSON-object output. Gemini sends the same prompt in `systemInstruction`, uses JSON MIME type plus an object schema, and reads the first candidate part. All adapters require a JSON object containing a string `romanized_text`; malformed/missing/blank output is an error.

### Prompt editing contract

The one shared Romanization prompt is `ROMANIZATION_PROMPT_V1` near the top of `src-tauri/src/bangla_romanization.rs`.

- Groq/OpenAI pass it as the system message.
- Gemini passes it as `systemInstruction`.
- The source Bangla transcript is passed separately as a user/content message.
- `romanize_bangla` validates this shared prompt before every provider request. It must remain non-empty and include the Romanization, JSON, and `romanized_text` requirements; otherwise no request is sent.
- If editing the prompt, preserve the instruction to return exactly one JSON object with the string field `romanized_text`; otherwise the validation fails and the raw-Bangla fallback is used.
- Do not include input text, keys, provider URLs, prompt contents, or raw response bodies in debug logs or UI events. When Debug Mode is on, safe diagnostics may include provider ID, model ID, status code, error category, request ID, and stage duration.

### Provider-scoped settings

`AppSettings` persists these separate fields:

```rust
bangla_romanization_provider_id
bangla_romanization_api_keys[provider_id]
bangla_romanization_models[provider_id]
bangla_romanization_timeout_seconds
```

The separate `bangla_romanization_enabled` boolean defaults to `true` for
backwards compatibility. When false, provider credentials and models remain
stored but are not read by the Bangla action.

The timeout is user-configurable from 5 to 120 seconds, defaulting to 45. Models are free-form, non-empty strings: the user can enter an exact provider-specific model ID in the settings UI. Existing selected models are preserved by the default-migration helper; only absent provider entries receive defaults. The one retired Handy Groq default, `llama-3.3-70b-versatile`, is migrated specifically to `openai/gpt-oss-120b`; other custom values are preserved.

## 7. Orchestration, paste, errors, and UI

`actions.rs::stop_bangla_recording` owns this exact ordering:

1. Stop the shared recorder and return to idle without a network request if it produces no samples or was cancelled.
2. Construct `RecordedAudio`; empty/oversized audio emits a transcription error and stops.
3. In streaming mode, finalize the active WebSocket after recorder drain. In batch mode, call `transcribe_bangla` directly; after a recoverable live failure, call it once as fallback.
4. Accept exactly one validated `BanglaTranscript`; on terminal STT failure, emit `bangla-transcription-error` and do not call an LLM or paste.
5. On a verified STT result with Romanization disabled, invoke `schedule_bangla_paste` with raw Bangla text and skip the LLM stage entirely.
6. With Romanization enabled, call `show_romanizing_overlay`, construct `RomanizationInput`, then call `romanize_bangla` through the same cancellation guard.
7. On Romanization success, `schedule_bangla_paste` invokes the existing `utils::paste` on the main thread.
8. On a non-cancellation Romanization failure, emit `bangla-romanization-error` and invoke `schedule_bangla_paste` with the already verified raw Bangla text.
9. On cancellation during any stage, suppress output and reset overlay/tray. `FinishGuard` still releases coordinator processing state.

The fallback in step 6 is an explicit product rule. It is not a generic provider fallback and does not try a second LLM provider.

`src-tauri/src/overlay.rs::show_romanizing_overlay` emits the `romanizing` overlay state. `src/overlay/RecordingOverlay.tsx` maps it to `overlay.romanizing`. The tray continues to use the shared `Recording`, `Transcribing`, and `Idle` states.

`src/App.tsx` listens for both `bangla-transcription-error` and `bangla-romanization-error`, displaying localized, content-free toast messages. `src/i18n/locales/*/translation.json` contains the `bangla.*` and `overlay.romanizing` keys in all supported locales.

## 8. Settings and typed IPC

The Bangla settings panel is `src/components/settings/bangla/BanglaSettings.tsx`. It contains two independent groups:

1. **Bangla transcription:** fixed Deepgram provider label, batch/streaming selector, endpoint, model, and Deepgram API key.
2. **Romanization:** an enabled toggle (default on), then the Groq/Gemini/OpenAI selector, provider-scoped API key, provider-scoped free-form model name, and timeout. The configuration controls are disabled—but retained—when Romanization is off.

The Rust setters are in `src-tauri/src/shortcut/mod.rs` and are registered in `src-tauri/src/lib.rs`:

```text
change_bangla_stt_provider_setting
change_bangla_stt_endpoint_setting
change_bangla_stt_api_key_setting
change_bangla_stt_model_setting
change_bangla_stt_mode_setting
change_bangla_romanization_enabled_setting
change_bangla_romanization_provider_setting
change_bangla_romanization_api_key_setting
change_bangla_romanization_model_setting
change_bangla_romanization_timeout_setting
```

Changing any Rust command signature, settings field, or exposed type requires regenerating `src/bindings.ts`; do not hand-edit that file. Frontend settings writes call the generated command and refresh settings after success.

## 9. Safety and non-goals

| Area               | Current contract                                                                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloud scope        | Only the Bangla binding makes cloud requests. Local shortcuts remain local. Disabling Romanization still uploads audio to Deepgram, but does not send transcript text to an LLM. |
| Sensitive data     | No API key, audio, Bangla text, Romanized text, raw provider response, or configured endpoint is emitted in Bangla logs/events.                                                  |
| Debug telemetry    | Debug mode records only provider/model metadata, status/error categories, request IDs, the STT transport path, and stage timings.                                                |
| Audio persistence  | No Bangla WAV/history entry is written.                                                                                                                                          |
| Cancellation       | Escape/cancel invalidates the recorder generation, drops in-flight stage futures, and blocks a late paste.                                                                       |
| Local inference    | Bangla does not load a local model, use a local batch/stream engine, or run local text normalization.                                                                            |
| Streaming          | The capture worker only performs a bounded non-blocking enqueue. WebSocket, PCM encoding, parsing, and finalization stay in an async worker.                                     |
| Focus              | The overlay is non-activating, but Handy does not capture or restore the target application's focus. Cloud latency can still allow focus drift before paste.                     |
| Credential storage | `SecretMap` is persisted settings data with redacted debug formatting; it is not an OS keychain implementation.                                                                  |
| Retry              | Streaming permits one batch fallback for recoverable live failures. There is no retry loop, backoff, or alternate-provider fallback.                                             |

## 10. Change guide

### Change the Romanization prompt or JSON output

Start in `bangla_romanization.rs` at `ROMANIZATION_PROMPT_V1`, `romanization_schema`, and `parse_json_result`. Keep `romanized_text` aligned in all three places. Test valid JSON, malformed output, and a non-empty result containing a residual Bangla character. Do not move this behavior into English post-processing.

### Add a Romanization provider

Add a `BanglaRomanizationProvider` implementation (or make the existing dispatch more modular), then update:

1. provider constants and `romanize_bangla` dispatch;
2. provider-scoped default API-key/model maps and migration in `settings.rs`;
3. provider validation in the four Romanization setters in `shortcut/mod.rs`;
4. provider option/label in `BanglaSettings.tsx` and every locale;
5. request/response/status mapping tests that do not expose real credentials.

Preserve the single result contract and the action-level fallback rule.

### Add or replace the transcription provider

Implement `BanglaTranscriptionProvider` in `src-tauri/src/bangla_transcription/`, dispatch it in `transcribe_bangla`, then adapt the STT settings defaults/validation/UI. Keep encoding, auth, request construction, response parsing, and status mapping inside the adapter. Keep `actions.rs` provider-neutral.

### Change fallback, cancellation, paste, or phases

Begin with `actions.rs::{stop_bangla_recording, complete_unless_cancelled, schedule_bangla_paste}`. Preserve all terminal paths: overlay/tray cleanup, coordinator `FinishGuard`, and cancellation checks before main-thread paste. Update `App.tsx`, all translation files, and `RecordingOverlay.tsx` together if event codes or states change.

### Change the Bangla hotkey or mode routing

Trace `transcription_mode.rs` → `settings.rs` default binding merge → `actions.rs::ACTION_MAP` → `transcription_coordinator.rs` → shortcut implementations and the general settings hotkey UI. The mode binding must stay recognized by the coordinator and macOS Secure Input fallback. Verify PTT, toggle, Escape, cross-mode busy rejection, microphone failures, and paste behavior.

### Change recorder/audio behavior

Start with `AudioRecordingManager::{try_start_recording, stop_recording, cancel_recording}` and the recorder/resampler/VAD code. Batch receives stopped 16 kHz mono samples; streaming receives the same filtered frames through `BanglaStreamingManager::feed`. Do not perform encoding, blocking sends, or network I/O on the real-time callback. Re-check the queue bound, nine-minute cap, final-frame ordering, and no-WAV-persistence rule if the captured representation changes.

## 11. Tests and verification

Relevant Rust tests live beside the code:

- `bangla_transcription/mod.rs`: empty transcript and nine-minute cap.
- `bangla_transcription/deepgram.rs`: PCM WAV construction, query parameters, nested response validation, status mapping, and a mock server checking token authentication plus binary upload.
- `bangla_transcription/deepgram_streaming.rs`: WebSocket URL/PCM encoding, final-segment ordering/de-duplication, recoverable empty results, mock-server auth/audio/finalization, and cancellation.
- `bangla_transcription/streaming.rs`: batch-mode absence and terminal missing-credential behavior.
- `bangla_romanization.rs`: provider-scoped settings, shared-prompt validation/injection, Groq structured-output selection, error mapping, JSON result validation, and acceptance of residual Bangla characters.
- `settings.rs`: Bangla binding/default migration, persisted Romanization opt-out, and provider maps without overwriting configured values.
- `transcription_mode.rs` and `transcription_coordinator.rs`: Bangla mode identity and PTT/release behavior.
- `actions.rs`: cancellation helper and overlay behavior.

After a relevant edit, run at least:

```bash
cd Handy/src-tauri && cargo fmt -- --check && cargo test --lib
cd Handy && bun run build && bun run lint && bun run check:translations
```

Regenerate bindings after Rust IPC changes, then type-check the frontend. Never use real Deepgram/Groq/Gemini/OpenAI credentials in automated tests; use a local mock server for transport contracts.

## 12. Remaining product decisions

- Whether cloud credentials should migrate from persisted settings to OS credential storage.
- Privacy/consent copy and data-retention policy for transmitted audio and text.
